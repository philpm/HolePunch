Your administrator account

Sign-in uses the account and random password shown by your deployment command. The administrator API token is a separate credential.

Changing your password signs out all web sessions. Sign in again with the new password after setup.

You can keep the generated password if you have stored it securely. Deployment summaries always show the initial credentials, not a password changed later.

Make the server reachable

Clients use this host and port to reach rathole. Use a public IP or a DNS-only hostname; an ordinary HTTP CDN proxy cannot carry this connection.

For random tunnel domains, point *.t.example.com at this server and enter t.example.com here. Leave it blank to use individual custom domains or TCP/UDP tunnels.

Panel and DNS

Current management URL
Configured panel domain

The panel domain comes from deployment. Change HP_PANEL_DOMAIN and restart the stack to use another panel domain.

Point the panel and each web tunnel domain to the server IP. Only add an AAAA record when the server has working IPv6.

Ports and existing websites

Keep the raw panel, Caddy Admin and internal gateway ports private. Public certificates need incoming port 80/443 to reach the configured HTTP/HTTPS listeners.

If Nginx or BT Panel already owns 80/443, plan the shared edge first. HolePunch can route existing loopback applications through Local websites; changing a listener port alone does not set up domain routing.

Check configuration synchronization and the rathole control listener before connecting a device.

Checks have not run yet.

These checks inspect the current saved configuration. Your draft settings are applied when you finish. Local readiness does not verify public DNS, provider firewall rules or end-to-end tunnel traffic.

If a check fails, you can still save setup and troubleshoot in Node settings. Existing website and firewall rules are never changed by this guide.

Publish your first local service

  1. Create a client in Clients. Give it a device name and copy its one-time enrollment code.
  2. Install holepunch-client on the computer running your local application. Run the command below and enter the enrollment code when prompted.
  3. Keep the CLI running. In Tunnels, select the client, protocol, local address and port, such as 127.0.0.1:8000.
  4. For Web, choose a domain with DNS pointed at this server. For TCP/UDP, use the assigned public port. Open the endpoint and test a real application request.
The desktop app is optional. All tunnel settings live in this console. Do not use the administrator API token as a client token.
Before inviting users, open Default policy to configure registration, client and tunnel counts, bandwidth and the platform domain suffix. Email delivery must be configured before opening registration or sending invitations. Individual limits are managed in User management.

How bandwidth limits work
1 Mbps = 1,000,000 bit/s, shared across both directions per tunnel. Disabled or offline tunnels retain their allocation. A limit of 0 disables the tunnel; re-enable it in Tunnels after increasing the limit. Changing a limit closes existing tunnel connections, so applications must reconnect.
