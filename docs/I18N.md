# Language and localization

[English](I18N.md) | [简体中文](zh-CN/I18N.md)

English is the source of truth for this repository: documentation, code comments, identifiers, CLI help, API diagnostics, and examples. The maintained web portal, compatibility console, and optional desktop GUI support **English (`en`)** and **Simplified Chinese (`zh-CN`)**. New installations default to English regardless of the OS/browser language.

The language selector is visible in both the sign-in header and the console header, including during Setup guide. It is available before login and persists per browser/webview under `holepunch.locale`. Unsupported or inaccessible saved settings fall back to English. Switching language keeps the current route and form values. Desktop also updates its tray menu. Accounts, commands, API field names, domains, user-entered resource names, and raw logs are not translated.

## Sources and packaging

| Path | Purpose |
|---|---|
| `web/locales/en.json` | Canonical English source messages; keys equal the English message |
| `web/locales/zh-CN.json` | Simplified Chinese translations with identical keys |
| `web/i18n.js` | Shared runtime, safe interpolation, locale persistence, and static HTML localization |
| `web/locales/catalogs.js` | Generated offline bundle committed for tool-free Rust builds |
| `scripts/sync-i18n.py` | Catalog parity, interpolation, template structure, and bundle validation |
| `tests/i18n.test.cjs` | Runtime fallback, persistence, interpolation, and data-preservation regression |

The web server embeds `/i18n.js` and `/locales/catalogs.js` alongside the console assets. Desktop `build.rs` copies them into its UI directory; these copies are ignored by Git. Tray labels read the source catalogs directly. No CDN or translation API is involved. Node is needed for UI tests, not server builds.

## Add or edit text

1. Write a clear English message and add it as both key and value in `en.json`.
2. Add the same key and its translation in every other catalog.
3. For dynamic UI text, use `HPI18n.t` (aliased as `tr` in applications). Tagged templates use numbered placeholders so translations can change word order.
4. Keep static HTML in English. The runtime captures catalog-backed text, titles, placeholders, and accessible labels before application scripts render. It does not observe or translate arbitrary user content later.
5. Regenerate the bundle and verify both languages, including empty/loading/error states and open dialogs.

```js
const {t: tr} = HPI18n;
button.textContent = tr('Save changes');
// Catalog key: "Request failed ({0})"
const message = tr`Request failed (${response.status})`;
```

A translated template can reorder `{0}`, `{1}`, and other placeholders, but must preserve their occurrences. Interpolation is single-pass: braces inside supplied values remain literal. Use complete sentences rather than constructing grammatical fragments for new messages.

Some existing table templates contain static HTML. Catalogs are trusted reviewed source, not user input. Preserve their markup and attribute structure; retain existing `esc`/`escape` calls for interpolated resource data. Prefer `textContent` for new plain messages. Never pass a fully rendered user-authored string to a translation lookup.

API diagnostics stay English and are not a stable error-code contract. The UI translates known messages; unknown framework/system diagnostics remain readable in English. Raw diagnostic details and rathole logs are preserved for support and searching.

Dates and times use the selected locale; bandwidth display uses locale number formatting while numeric form values and wire fields remain language independent.

```sh
python3 scripts/sync-i18n.py
python3 scripts/sync-i18n.py --check
node --test tests/i18n.test.cjs
cargo build --workspace --locked
```

CI checks catalog parity and generated output. English prose remains authoritative; translated documents link to their source and record its content revision.

## Add another locale

Copy the English JSON to a BCP 47 locale filename and translate every value. Add its native-language option to each HTML selector and extend desktop `set_locale` to read the same catalog for tray labels. Regenerate the bundle, then test persistence, interpolation, layout, keyboard access, and desktop packaging. Languages requiring right-to-left layouts need explicit layout support before being advertised.

## Documentation translations

`README.md` is the English project homepage; `README-zh.md` is its Simplified Chinese counterpart. Other translated guides live in `docs/zh-CN/`, with links back to English and the Chinese index. English remains the canonical reference; the Apache license text is distributed unchanged.

Keep examples, commands, API paths, environment variables, and code comments identical to the English source. Translate the surrounding explanations, headings, and tables. Update both languages together when behavior changes. Each translation records its repository-relative source path and SHA-256 content revision in a `translation-source` HTML comment. After reviewing the translated content, update that digest with `sha256sum SOURCE` (Linux) or `shasum -a 256 SOURCE` (macOS). The repository hygiene check rejects stale source revisions; changing only the digest is not a translation update.
