# Getting help

[English](SUPPORT.md) | [简体中文](docs/zh-CN/SUPPORT.md)

Start with the [documentation index](docs/README.md), installation guide, and troubleshooting in the deployment guide. This is community-supported development software; no response-time or production support guarantee is offered.

Search [existing issues](https://github.com/philpm/HolePunch/issues) before filing a bug or feature request. Include the version or commit, operating system and architecture, installation method, interface language, reproduction steps, and expected versus actual behavior.

Use generic hostnames and redact logs. Never attach environment files, access summaries, database backups, private keys, enrollment codes, session cookies, or customer information. Report vulnerabilities through [Security](SECURITY.md), rather than a public issue.

To contribute code or translations, see [Contributing](CONTRIBUTING.md) and [Localization](docs/I18N.md).
